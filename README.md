# Frame

Frame is an experimental productivity workspace that treats documents, data, and presentations as different views over the same structured work.

This repository contains a local-first React prototype plus the beginnings of a testable workspace engine for shared objects, dependency lineage, semantic formulas, and change history.

## What is implemented

- **Shared workspace shell** for navigating Docs, Data, and Present surfaces.
- **Frame Docs** with editable strategy content, live business metrics, a connected decision object, and source-aware UI.
- **Frame Data** with a typed regional revenue table, editable values, simple analysis, live charting, and a semantic table schema.
- **Frame Present** with a narrative/storyboard interface and a presentation scene derived from the same live metrics used elsewhere.
- **Workspace dependency graph** with stable IDs for documents, metrics, regions, decisions, and presentation scenes.
- **Downstream impact detection** so a change can identify which objects and surfaces depend on it.
- **Semantic change history** generated by shared-object mutations.
- **Source/provenance records** attached to the workspace model.
- **Semantic formula engine** supporting expressions such as `SUM(Regions.Revenue)` rather than cell coordinates.
- **Cross-surface propagation**: changing regional revenue recalculates the shared Q2 revenue metric, which immediately updates Docs and Present.
- **Command palette** (`Cmd/Ctrl + K`) with deterministic prototype actions for navigating, adding evidence, approving a shared decision, and resetting the demo.
- **Local persistence** through `localStorage`, including migration of older saved prototype state into the newer workspace schema.

## Run locally

Node 22.6+ is required.

```bash
npm install
npm run dev
```

## Local testing

GitHub Actions is intentionally not used while hosted Actions usage is unavailable. The repository's primary validation path is local.

The core model tests have no third-party test-runner dependency and use Node's built-in test runner:

```bash
npm test
```

Watch them while developing:

```bash
npm run test:watch
```

Type-check the application:

```bash
npm run typecheck
```

Run tests, TypeScript validation, and the production Vite build:

```bash
npm run verify
```

Current core coverage includes semantic formulas, metric recalculation, transitive dependency propagation, decision propagation, legacy workspace hydration, formatting, and invalid mutation/reference failures.

## Current architecture

```text
src/
  App.tsx        Product surfaces and interaction layer
  formulas.ts   Typed semantic formula parser/evaluator
  model.ts       Workspace graph, schemas, mutations, lineage, seed data
  main.tsx       React entrypoint
  styles.css     Product visual system and responsive layouts

tests/
  formulas.test.mjs
  model.test.mjs
```

The React layer now delegates important shared-object mutations to the workspace engine. The next goal is to move more UI behavior behind explicit commands/mutations rather than editing nested state directly.

## Product principles encoded in the prototype

1. **Projects before files.** The workspace is the primary unit; document, data, and presentation views live inside it.
2. **One object, many representations.** Metrics and decisions retain identity across surfaces rather than being copied.
3. **Purpose-built surfaces.** Docs, Data, and Present have different interaction models even though they share underlying objects.
4. **Meaning before coordinates.** Data formulas reference tables and fields such as `Regions.Revenue`, not accidental cell positions.
5. **Inspectable automation.** AI-like actions should operate on structured objects and become previewable changes rather than opaque chat output.
6. **Compatibility later, native model first.** DOCX/XLSX/PPTX import/export will matter, but the internal model should not inherit their limitations.

## Suggested next milestones

### 1. Strengthen the object graph

- Computed metric definitions stored as first-class objects
- Formula dependencies merged into the workspace graph
- Reversible mutations / undo transactions
- Semantic diffs between versions
- Stronger source/provenance locators and freshness state

### 2. Strengthen Docs

- Rich-text editor with semantic blocks
- Claims and citations
- Slash/command insertion
- Inline object embeds
- Comments, decisions, owners, approvals

### 3. Strengthen Data

- Formula editor/autocomplete for semantic references
- Multiple tables and relations
- Model/dependency view
- Reusable metric definitions
- Chart definitions as reusable objects
- Additional formula operations, filters, and grouped aggregation

### 4. Strengthen Present

- Scene selection and editing
- Semantic slide components
- Constraint-based layout engine
- Themes/design tokens
- Speaker notes and presentation mode
- Explicit links from slide components back to source objects

### 5. Collaboration and storage

- Server-backed workspace persistence
- Authentication and permissions
- Realtime multiplayer/CRDT layer
- Semantic version history
- Export/import adapters

## Status

This is an intentionally narrow vertical slice, not a production office suite. Its job is to validate the foundational thesis: **a document, spreadsheet, and presentation can remain distinct tools while operating on the same connected model of work.**
