# Local Office interoperability testing

Frame treats local interoperability tests as canonical. GitHub Actions are not required for this workflow.

## Fast automated interoperability suite

Run:

```bash
npm run test:interop
```

This focused suite covers:

- bounded Office ZIP reading;
- DOCX/PPTX/XLSX semantic import;
- import fidelity warnings;
- source-aware re-import synchronization;
- DOCX/PPTX/XLSX compatibility export;
- Word numbering/review export;
- Google Workspace export-to-Office planning;
- Google Drive read-only discovery/export transport; and
- imported Data/formula preservation.

Run `npm run verify` before considering a larger change complete; the focused suite is a faster inner loop, not a substitute for the full project suite and TypeScript/Vite build.

## Generate Frame exports for manual Office testing

Run:

```bash
node --experimental-strip-types scripts/generate-office-fixtures.mjs
```

By default the script writes a DOCX, PPTX, XLSX and a small QA README into your operating system temp directory under `frame-office-fixtures`.

To choose a destination:

```bash
node --experimental-strip-types scripts/generate-office-fixtures.mjs ./tmp/office-fixtures
```

Manual checks:

### Word / Google Docs

- The document opens without a repair prompt.
- Heading styles are recognizable.
- Bullet and numbered blocks are native lists, not literal bullet/number prefixes.
- Live metric content appears as a table.
- Decision/review context is readable.
- Imported source provenance is visible.

### PowerPoint / Google Slides

- The deck opens without a repair prompt.
- Visible Frame scene order matches the deck order.
- Scene source text is visible but does not obscure main content.
- Speaker cues appear in the Notes pane.
- Speaker cues do **not** appear as visible `Speaker note:` body text.
- Slide navigation works normally.

### Excel / Google Sheets

- The workbook opens without a repair prompt.
- Regions and Plan sheets contain current semantic values.
- Imported foreign tables are present.
- Sheet names are unique case-insensitively and do not exceed Excel's 31-character limit.
- The formula fixture contains its cached value but does not re-emit the preserved foreign formula.

If Microsoft Office reports that it repaired an export, keep the repaired file and exact repair message as a regression fixture before changing the writer.

## Inspect a real Office/Google export before importing

Use:

```bash
node --experimental-strip-types scripts/inspect-office-import.mjs path/to/file.docx
node --experimental-strip-types scripts/inspect-office-import.mjs path/to/file.pptx
node --experimental-strip-types scripts/inspect-office-import.mjs path/to/file.xlsx
```

The command does **not** mutate a workspace. It prints:

- detected Office kind;
- imported item count;
- semantic command mix;
- fidelity warnings;
- imported document-block count;
- retained foreign tables and preserved formula counts; and
- imported presentation scenes and note presence.

Machine-readable output:

```bash
node --experimental-strip-types scripts/inspect-office-import.mjs path/to/file.xlsx --json
```

This is useful when a customer workbook or deck behaves differently from synthetic fixtures: capture the inspector output together with the source application's version and the sanitized source file.

## Recommended external fixture set

Keep a small, sanitized local fixture corpus generated by current Microsoft 365 and Google Workspace versions:

- Word: headings, nested lists, table, image, comment, tracked edit, footnote, header/footer.
- PowerPoint: reordered slides, speaker notes, table, image, chart, SmartArt, animation/transition.
- Excel: shared strings, inline strings, booleans, dates, percentages, merged cells, comments, formulas, shared formulas, external link, hidden sheet, unusual sheet names.
- Google Docs/Slides/Sheets: download each of the above into DOCX/PPTX/XLSX and run the same inspector.

Do not commit confidential customer content. Prefer hand-built or sanitized fixtures whose expected semantic result is clear.

## Regression rule

When an interoperability bug is found:

1. reduce it to the smallest non-confidential Office package that still reproduces the issue;
2. add an automated regression when the behavior can be represented in the Node test suite;
3. keep fidelity loss explicit as a warning until Frame can represent it safely; and
4. never make the parser silently discard a previously preserved semantic or provenance field to satisfy an import.
